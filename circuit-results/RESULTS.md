# DAVINCI results guest — Specification

`circuit-results` is a small ZisK guest that proves the tally of one DAVINCI
election under a single ElGamal key. It takes the final state root of the
process, proves that the encryption key (state key `0x03`) and the net results
accumulator (state key `0x04`) are leaves of that tree, and verifies one
Chaum–Pedersen decryption proof per ciphertext of the accumulator. The PLONK
wrap of this proof is verified on-chain by the same ZisK verifier as the batch
proofs, under its own program vk; the settlement contract then checks that the
published `state_root` is the process's last root and reads the tallies.

The guest sources are `circuit-results/src/main.rs`; the host builder is
`input-gen/src/results.rs` (`build_results_input`, binary `gen-results-input`);
the service route is `POST /results`. Keep all four and this file in step.

---

## 1. Input frame

The guest reads one `read_slice` frame (the service and `ziskemu` add the
u64 LE length prefix). All integers are little endian. `Fr` is 32 bytes, the
little-endian encoding of an integer (arbo / `FrRaw` convention, i.e. what
the JSON carries as arbo-LE hex). `Digest` is 32 raw SHA-256 bytes.

| Offset | Size | Field | Notes |
|---:|---:|---|---|
| 0 | 8 | magic | `"DAVRSLT1"` as a u64 LE |
| 8 | 32 | `state_root` | Digest: the arbo root bytes |
| 40 | 32 | `pk_x` | Fr, TE x of the election key |
| 72 | 32 | `pk_y` | Fr, TE y |
| 104 | 8 | `n_key` | u64, must equal `SMT_LEVELS` = 64 |
| 112 | 64×32 | `key_siblings` | Digest each, root→leaf, zero-padded |
| 2160 | 64×32 | `accumulator` | Fr each, `[c1x, c1y, c2x, c2y] × 16`, TE |
| 4208 | 8 | `n_acc` | u64, must equal 64 |
| 4216 | 64×32 | `acc_siblings` | Digest each, root→leaf, zero-padded |
| 6264 | 16×8 | `results` | u64 claimed plaintext per ciphertext |
| 6392 | 16×160 | `cp` | per ciphertext: `a1x a1y a2x a2y z` (Fr each) |
| 8952 | | end | total length is exactly 8952 bytes |

Anything else (wrong magic, `n_key`/`n_acc` ≠ 64, short frame, trailing bytes)
is a parse failure: the guest sets `FAIL_PARSE`, skips every check and
commits `ok = 0`.

The host builder accepts sibling lists of 1..=64 entries and zero-pads them to
64 (trailing zero siblings do not change an SMT inclusion proof); more than 64
is rejected host-side.

### JSON (`POST /results`, `gen-results-input --request`)

All 32-byte values are arbo-LE hex, exactly 32 bytes, `0x` optional (the same
convention as `ResultsPayload` / `ChainConfig`):

```json
{ "state_root": "..", "enc_key_x": "..", "enc_key_y": "..",
  "key_siblings": [".."], "accumulator": [64 × ".."], "acc_siblings": [".."],
  "results": [16 × u64],
  "cp_proofs": [16 × {"a1x": "..", "a1y": "..", "a2x": "..", "a2y": "..", "z": ".."}] }
```

`state_root` is `hex(root bytes)` as returned by arbo `tree.Root()`.
`z` is the response scalar reduced mod the subgroup order `l`.

## 2. Checks

`p` is the BN254 scalar field modulus (the BabyJubJub base field) and
`l = 2736030358979909402780800718157159386076813972158567259200215660948447373041`
the order of the prime subgroup generated by `B8`.

### 2.1 Canonical encodings (`FAIL_RANGE`)

- `pk_x`, `pk_y`, all 64 accumulator coordinates and every `a1x a1y a2x a2y`
  must be `< p`.
- Every `z` must be `< l` (the Go and Rust provers emit `z mod l`).

The SMT leaf hashes bind raw bytes, not residues, and the CP challenge hashes
the raw `y` coordinates, so a second encoding `x + p` of the same point would
otherwise give the host a second leaf hash or a second challenge for one
point. `state_root` and siblings are SHA-256 outputs, not field elements, and
are not range-checked.

### 2.2 Election key (`FAIL_KEY`)

`pk` must be on the curve (`a·x² + y² = 1 + d·x²·y²`), not the identity
`(0, 1)`, and in the prime subgroup (`l · pk = O`). The subgroup multiply only
runs on an on-curve point.

### 2.3 Key inclusion (`FAIL_INCL_KEY`)

`verify_inclusion(state_root, 0x03, hash_enc_key(pk_x, pk_y), key_siblings)`,
with `hash_enc_key = int_be(sha256(pk_x_BE32 ‖ pk_y_BE32))` (the genesis leaf
value, `circuit-primitives/src/hash.rs`). This pins `pk` to the key the batch
guests encrypted to.

### 2.4 Accumulator inclusion (`FAIL_INCL_RESULTS`)

`verify_inclusion(state_root, 0x04, ballot_leaf_hash(accumulator), acc_siblings)`
with `ballot_leaf_hash = int_be(sha256(64 coords, each BE32))`
(`circuit-primitives/src/results.rs`).

`verify_inclusion` is the circomlib `SMTVerifier` inclusion case over the arbo
SHA-256 tree (`circuit-primitives/src/smt.rs`): leaf
`sha256(key_le8 ‖ value_le32 ‖ 0x01)`, node `sha256(l ‖ r)`, path bits
LSB-first, the leaf level is the last non-zero sibling.

### 2.5 Decryption proofs (`FAIL_CP`)

For each ciphertext `i` in `0..16`, with `C1 = (acc[4i], acc[4i+1])`,
`C2 = (acc[4i+2], acc[4i+3])` and `m = results[i]`,
`chaum_pedersen::verify_decryption(pk, C1, C2, m, cp[i])`:

```
all of pk, C1, C2, A1, A2 on the curve
D  = C2 − m·B8
e  = Poseidon12(rte(pk), rte(pk), rte(C1), rte(D), rte(A1), rte(A2))
z·B8 == A1 + e·pk   and   z·C1 == A2 + e·D
```

`rte(x, y) = (x·(−f), y)` is the gnark reduced form used only inside the
hash. The first failing index goes to register 42.

Padded fields (`i >= num_fields`) hold the identity ciphertext
`((0,1),(0,1))`; for them the equations force `A2 = e·m·B8` with `e` a hash of
`A2`, so only `m = 0` can be proven. The guest does not read `num_fields`.

The claimed `m` is a u64, below `l`, so it is the unique plaintext of the
ciphertext. No discrete log runs in the guest.

### 2.6 Verdict

`ok = (fail_mask == 0)`. All checks after parsing run regardless of earlier
failures (none of them can panic on hostile input), so `fail_mask` reports
every violated rule.

## 3. Output registers

43 u32 registers, committed as LE bytes (`commit_slice`); ZisK publics
43..63 are zero.

| Reg | Name | Value |
|---:|---|---|
| 0 | `ok` | 1 if every check passed, else 0 |
| 1 | `fail_mask` | §4 |
| 2..9 | `state_root` | LE u32 limbs of the raw root digest: `reg[2+j] = u32_le(root[4j..4j+4])` |
| 10..41 | `results` | `reg[10+2i] = lo32(results[i])`, `reg[11+2i] = hi32(results[i])` |
| 42 | `cp_fail_index` | first failing CP index, or `0xFFFFFFFF` |

When `ok = 0`, registers 2..41 are zero. A consumer that forgets to check
`ok` then still cannot match a real root or read a tally.

---

## 4. Fail-mask reference

| Bit | Name | Meaning |
|---:|---|---|
| 0 | `FAIL_PARSE` | malformed frame (§1); nothing else is checked |
| 1 | `FAIL_KEY` | key off-curve, identity or outside the prime subgroup |
| 2 | `FAIL_INCL_KEY` | key leaf `0x03` not included under `state_root` |
| 3 | `FAIL_INCL_RESULTS` | accumulator leaf `0x04` not included under `state_root` |
| 4 | `FAIL_CP` | a Chaum–Pedersen proof failed (index in reg 42) |
| 5 | `FAIL_RANGE` | non-canonical coordinate (`≥ p`) or scalar `z ≥ l` |

---

## 5. What the verifier must still check

- PLONK verification under the pinned results program vk
  (`CircuitRelease.ResultsVK` in `go-sdk/chain/release.go`).
- `ok == 1`.
- `state_root` equals the process's last settled root. The guest proves the
  tally of whatever root it is given; binding it to the right process and to
  the end of the voting window is the contract's job.

The key is pinned transitively: it is proven to be the `0x03` leaf of that
root, which the batch guests keep unchanged from genesis.

---

## 6. Tests

`go-sdk/tests/integration/results_cheat_test.go` (`TestResultsCheat`, ziskemu,
no GPU) builds a valid input for a small election and one tampered input per
rule: wrong root, another key with valid proofs under it, a changed
accumulator coordinate, a wrong plaintext, a forged `z`, a key outside the
subgroup, an `x + p` coordinate, a `z + l` scalar, and truncated / padded
frames.
