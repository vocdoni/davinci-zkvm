# davinci-zkvm Go SDK

Go client library for the `davinci-zkvm` service.

The active request path is STARK-only:

- `stark_proofs`
- `ecgfp5_reencryption`
- `ecgfp5_ballot_proofs` inside `state`

## Batch sizing and proof generation

- `DAVINCI_MAX_BATCH_SIZE`
  - Go-side integration cap for `VOTES_PER_BATCH`
  - must be a power of two
  - default: `128`
- `VOTES_PER_BATCH`
  - per-transition target batch size used by the integration tests
  - rounded down to the largest power of two not exceeding `DAVINCI_MAX_BATCH_SIZE`
- `DAVINCI_STARK_MAX_CONCURRENCY`
  - max number of concurrent `davinci-stark` WASM ballot proofs generated by the Go integration helpers
  - default: `8`

For the Rust `input-gen` crate and the zkVM circuit, `DAVINCI_MAX_BATCH_SIZE`
is a build-time setting. Build those crates with the same value you use from
the Go side.

## Core usage

```go
client := davinci.NewClient("http://localhost:8080")
jobID, err := client.SubmitProve(&davinci.ProveRequest{
    StarkProofs: proofBundles,
    Sigs:        sigs,
    State:       state,
    CensusProofs: censusProofs,
    Ecgfp5Reencryption: reenc,
    KZG:         kzg,
})
```

## Main types

- `ProveRequest`
- `StateTransitionData`
- `StarkProofBundleJson`
- `Ecgfp5BallotProofData`
- `Ecgfp5ReencryptionData`
- `CensusProof`
- `CspData`
- `KZGRequest`
- `PublicOutputs`

## Encoders

The SDK exposes binary block encoders used by tests and offline tooling:

- `EncodeStateBlock`
- `EncodeCensusBlock`
- `EncodeEcgfp5ReencBlock`
- `EncodeKZGBlock`
- `EncodeCspBlock`
